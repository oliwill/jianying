# 拣影

> Mac 上插卡 → 挑片 → 进相册，一条路走完。

macOS 的「照片」App 是个数据库，不是文件夹。你没法把 SD 卡里的照片直接拖进去浏览——只能先导入，导入完还得在图库里再筛一遍。拣影就是补上这个缺口：**在导入之前，先把照片挑干净**。

原生 SwiftUI，无 Electron，无第三方依赖，1 个 .app 直接跑。

---

## 它做什么

```
SD 卡 / 任意文件夹
      ↓  0.6 秒扫描（照片立刻出现，拍摄时间后台补）
  网格浏览 + 键盘挑片
      ↓  空格＝留，X＝弃
  只把「留」的导进「照片」
```

也可以选择不来照片库：直接**复制到文件夹**，按拍摄日期自动建子目录。

---

## 用法

### 打开

- 菜单 `文件 → 打开文件夹…`（⌘O）
- 或者直接把 SD 卡文件夹**拖进窗口**

SD 卡在 Finder 侧边栏里点进去，通常选 `DCIM` 就行——拣影会递归扫描所有子目录。

### 挑片

| 按键 | 作用 |
|---|---|
| `空格` / `S` / `1` | 保留 |
| `X` / `2` | 弃用 |
| `←` `→` `↑` `↓` | 移动光标（上下按列数跳） |
| `Delete` | 撤销当前标记，回到「未筛」 |
| 双击缩略图 | 标记保留并自动跳下一张 |

标记完会自动跳到下一张（工具栏可关）。左侧栏按状态筛选，随时切到「保留」检查一遍。

### 导入

右下角 **导入「照片」** —— 只把标记为「保留」的传进去，弃用的不碰。

第一次会请求权限。去 `系统设置 → 隐私与安全性 → 照片` 里勾选「拣影」。

想要文件而不是图库，用 **复制到文件夹…**，会按 EXIF 拍摄日期建 `2025-11-17/` 这样的子目录，重复复制自动跳过不产生副本。

## 支持的格式

**图片** JPG / HEIC / PNG / TIFF / GIF / WebP
**RAW** ARW(Sony) / CR2 / CR3 / NEF / RAF / ORF / RW2 / DNG / PEF / SRW / 3FR / IIQ 等 30 余种
**视频** MOV / MP4 / M4V / MTS

RAW 走 ImageIO 解码，能看到缩略图和内嵌预览。Sony 的 `.ARW` 实测正常。

## 性能

实测对象：5405 张 Sony JPEG（10–14 MB/张），SD 卡直读。

| 指标 | 数值 |
|---|---|
| 扫描到可交互 | **0.6 秒**（拍摄时间后台补，不阻塞） |
| 5405 张 EXIF 全补完 | 约 19 秒（后台进行，不影响操作） |
| 缩略图冷读 | 231 ms/张 → **缓存后 0.12 ms** |
| 首屏 30 张 EXIF 预览 | 78 ms |
| 大图预览（2400px） | 90 ms |
| 5400 张缓存占用 | 157 MB |

三个关键优化，都是实测调出来的：

1. **渐进式扫描** — 先枚举文件（0.5s）让用户马上能看，EXIF 时间在后台分批补、补完再重排。原本一次性读完要 20 秒，改完是 0.6 秒可用。
2. **磁盘缩略图缓存** — 存在 `~/Library/Caches/com.alma.jianying/thumbs`。缓存键绑了文件大小和修改时间，文件换了会自动失效。冷读 231ms → 热读 0.12ms，差 1500 倍。
3. **两阶段解码** — 先上相机内嵌的 160×120 预览（0.6ms/张，网格瞬间有内容），后台再换 360px 清晰图。直接生成 360px 要 231ms，全部铺满会卡死。

另外 `CGImageSourceCreateWithURL` 的 options 字典必须显式关掉 `kCGImageSourceShouldCache` 和 `kCGImageSourceShouldAllowFloat`，否则 ImageIO 会做完整解码，单张 EXIF 读取从 0.3ms 变成 4.8ms。

## 构建

需要 Xcode Command Line Tools（`xcode-select --install`），不需要完整 Xcode。

```bash
./build.sh          # 产物: 拣影.app
open 拣影.app
```

跑验收测试（39 项，需插入 SD 卡做真实图片测试）：

```bash
./Tests/build.sh
```

```
结果: 39 通过 / 0 失败
```

覆盖：扫描、EXIF 解析、时间排序、三种标记状态、筛选、键盘边界、撤销、批量操作、按日期复制、重复去重、缩略图尺寸、大图分辨率、磁盘缓存往返、空目录、非图片文件忽略、空列表操作不崩溃。

### 端到端导入验证（已实测通过）

照片导入这条链路真机验证过，过程：

```
授权 addOnly = authorized
导入前照片库: 68 张
performChanges ok=true, err=none
导入后照片库: 71 张   ← 增加 3，写进成功
清理测试照片: 成功，剩余 68 张   ← 恢复原状，无残留
```

验证用的是一份临时开启「访问所有照片」的构建，确认写入真的落库后立即删除了测试照片，并已把权限恢复为 `addOnly`。

**关于权限设计**：拣影只申请 `.addOnly`（只写不读）。这意味着它能把照片放进图库，但**读不到你已有的任何照片**。这是故意的——挑片不需要看你过去的照片，权限越小越好。代价是它自己也无法确认"导入后长什么样"，只能依赖 PhotoKit 的写入回调结果。

## 已知限制

- **标记不持久化**。关掉窗口，保留/弃用状态就没了。这是有意的——它是「一次挑完就走」的工具，不是图库。想要中途离开就一次挑完再关。
- **没有撤销历史**。只有当前这张能撤销（Delete 键回到未筛），没有 ⌘Z 栈。
- **导入不做 RAW+JPG 配对**。如果同一次拍摄同时有 `.ARW` 和 `.JPG`，两个都会进照片库（照片 App 会自己合成一张）。
- **ad-hoc 签名**。第一次打开可能需要在 系统设置 → 隐私与安全性 里点「仍要打开」。要分发给别人得用开发者证书重签。
- **只支持 arm64**。Intel Mac 需要改 `build.sh` 里的 `-target` 参数。

## 为什么不用现成的

| 方案 | 缺什么 |
|---|---|
| Finder 画廊视图 | 缩略图慢，不能看 RAW，没法批量标记 |
| 「照片」App | 必须先导入才能看，导入完还得再筛一遍 |
| Adobe Bridge | 有，但要订阅，启动重，不是为「快速筛完就走」设计的 |
| XnView MP | 能浏览能标记，但导入照片库这一步要另外想办法 |

拣影只解决一件事：**插卡到导入之间那 10 分钟**。别的事不干。
